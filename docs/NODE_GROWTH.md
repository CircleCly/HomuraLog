# 世界线节点增长策略

HomuraLog 必须保持“操作前缀不同就是不同世界线”，因此不会用最终状态去合并节点。当前实现采用以下方式控制规模：

- 内存和存档继续使用前缀树；共同前缀天然只保存一次。
- 全屏图优先显示当前路径和高访问分支，单次最多创建 600 个 Godot 图节点，避免超大树阻塞战斗 UI。
- 超出显示上限时只做视图裁剪，并明确显示“已显示/总节点”；JSON 中的完整记录和“已探索”判断不受影响。
- 侧栏默认折叠非当前分支，日常操作不需要展开整棵树。

后续可选优化按风险排序：

1. 把 JSON 的嵌套节点改成扁平节点表，减少重复字段并消除递归深度成本。
2. 为全屏图增加按回合、结果和访问次数过滤，以及折叠连续无分叉链。
3. 对已经离开房间的归档使用 gzip；当前战斗仍保留可恢复的完整树。
4. 只在用户明确启用有损归档时，才把很旧的单次中止叶节点替换为计数摘要。

不采用“相同 HP/能量/敌人状态就合并”的方案，因为隐藏 RNG、能力状态和动作顺序可能不同，也违反严格世界线语义。
